## 데이터 모드 — 다른 모드와 함께 잘 돌게

게임은 모드 목록을 위에서 아래로 읽습니다. 아래 내용은 시험 모드를 만들어 게임에서 확인한 규칙이고, 모드매니저가 겹침을 판단할 때 쓰는 규칙이기도 합니다.

**목록에 나오게 하기**

- `ModInfo.json` 은 `{ … }` 하나가 아니라 `[ { … } ]` 목록으로 씁니다. 목록이 아니면 게임이 읽지 못하고 건너뜁니다.
- `strIDEnd` 는 다른 모드와 겹치지 않게 정하고, 버전이 바뀌어도 그대로 둡니다. 게임은 이 ID 로 모드를 구분합니다.
- 한 압축에 같은 `strIDEnd` 의 모드를 여러 개 넣으면 모드매니저가 모두 보여 주고 함께 켜면 부딪힌다고 알립니다. 가장 늦게 바뀐 것에는 `(최신)` 을 붙입니다.

**표는 줄 전체를 덮습니다**

- 같은 표의 같은 번호를 두 모드가 바꾸면 아래 모드가 이깁니다. 칸 단위로 합쳐지지 않으므로, 위 모드가 바꾼 칸도 아래 모드 줄에 있는 값으로 돌아갑니다.
- 그래서 **실제로 바꾼 줄만** 넣어 주세요. 고치지 않은 원작 줄을 복사해 두면 다른 모드의 변경을 지울 수 있습니다.
- 새 항목은 번호 끝에 `strIDEnd` 를 붙인 새 번호로 만듭니다(예: `strIDEnd` 가 `abcd` 면 `1000001abcd`). 새 번호는 다른 모드와 겹치지 않습니다.
- 새 게임의 무력·소속·도시 등은 시나리오 무장 표(`GameStoryHero`)가 다시 정합니다. `Hero` 만 바꾸면 새 게임에 보이지 않습니다.

**덧붙이는 표는 순서를 탑니다**

- `…EC`·`…CC`·`Conversation` 표의 줄은 덮지 않고 덧붙습니다. 부모 표는 파일 이름에서 `EC`·`CC` 를 뗀 것입니다(`Conversation` 의 부모는 `ConversationInfo`).
- 원작 항목에 줄을 붙였는데 목록에서 그 아래 모드가 같은 항목의 부모 줄을 바꾸면, 붙인 줄이 사라집니다. 덧붙인 모드가 아래에 있으면 둘 다 적용됩니다.

**카드 연출은 새 번호로 만드는 것이 가장 안전합니다**

- 원작 카드 번호의 연출(`BattleCardAnimation\<원작 카드 번호>.dat`)은 **켜진 데이터 모드 중 맨 아래 모드 것만** 나옵니다. 아래에 데이터 모드가 하나라도 있으면, 그 모드에 연출 파일이 없어도 원작 연출로 돌아갑니다. 그래서 이런 모드가 둘이면 하나의 연출은 나오지 않습니다.
- **새로 넣은 카드(꼬리 붙은 번호)의 연출은 순서와 상관없이 나옵니다.** 가능하면 원작 카드를 고치지 말고 새 카드로 만들어 주세요.
- 원작 번호의 연출을 꼭 바꿔야 한다면 게시글이나 모드 설명에 '켜진 데이터 모드 중 목록 맨 아래에 두어야 한다'고 적어 주세요.

**NPC 메뉴가 있다면 빈 파일 하나를 넣어 주세요**

- `InteractOption.json` 으로 다른 모드와 같은 `optionID` 줄까지 고치는 모드에 `ConversationCondition.json` 이 없으면, 목록에서 그 뒤에 이 파일이 있는 모드가 없을 때 메뉴가 통째로 보이지 않습니다.
- 메뉴가 있는 모드는 빈 내용(`[]`)이라도 이 파일을 넣어 두면 안전합니다. 새 메뉴만 넣거나 건물 버튼(`type` 5)만 있으면 이 문제는 생기지 않습니다.

**그림은 표와 반대입니다**

- 같은 경로의 그림을 두 모드가 넣으면 **위쪽** 모드 그림이 나옵니다.
- 모드매니저는 그림 묶음 `AssetBundlesImage\image_<strIDEnd>` 옆의 `.manifest` 로 겹침을 비교합니다. `.manifest` 를 함께 넣지 않으면 겹침을 알려 주지 못합니다.

**모드매니저 딱지의 뜻**

모드매니저는 겹치는 줄을 게임 원본과 비교해서 각 모드가 실제로 무엇을 바꿨는지 봅니다.

| 딱지 | 뜻 |
|---|---|
| `겹침 N · 함께 사용 가능` | 아래 모드와 같은 항목을 고치지만 원래대로 돌아가는 변경은 없습니다. 두 모드가 같은 칸을 다르게 고쳤다면 아래 모드 값이 적용됩니다 |
| `겹침 N · 이 모드 것이 적용` | 위와 같은 경우에 아래쪽 모드에 붙습니다 |
| `⚠ 겹침 N · 순서 바꾸면 해결` | 한쪽의 변경이 원래대로 돌아가지만, 순서를 바꾸면 둘 다 적용됩니다 |
| `⚠ 겹침 N · 기능 빠질 수 있음` | 이 모드의 변경이 아래 모드 줄에 덮여 원래대로 돌아갑니다 |
| `⚠ 메뉴 안 보임` | 위 'NPC 메뉴' 규칙에 걸립니다 |
| `⚠ 카드 연출 안 나옴` | 위 '카드 연출' 규칙에 걸립니다 |
| `그림 겹침 N` | 같은 경로의 그림을 넣습니다 |

다른 모드와 같은 줄을 꼭 고쳐야 한다면, 그 모드의 변경까지 담은 호환판을 만들어 그 모드 아래에 두게 하면 변경이 사라지지 않습니다.


## 모드 정보 파일 (loh-mod.json) — 양식 버전 1

모드 폴더에 이 파일 하나를 넣어 두면, 모드매니저가

- **게시글 링크**를 알아서 걸고 (사용자는 '게시글 열기' 한 번으로 본문에 감),
- **업데이트 확인** 때 이 모드도 함께 확인하고 (게시글 제목의 버전과 비교),
- **설정 파일(ini)** 을 '설정 열기' 버튼으로 바로 열어 주고,
- 켜 둔 **다른 DLL 모드와 같은 곳을 고치는지** 비교해 알려 줍니다.

이 파일이 없어도 사용자는 모드매니저에서 게시글 링크를 직접 넣을 수 있습니다.

### 어디에 두나

| 모드 모양 | 파일 이름과 자리 |
|---|---|
| DLL 이 자기 폴더에 있음 (`게임\내모드\내모드.dll`) | `게임\내모드\loh-mod.json` |
| 데이터 모드 (`게임\MODs\내모드\`, 창작마당 모드는 그 모드 폴더) | `게임\MODs\내모드\loh-mod.json` |
| DLL 을 게임 폴더에 바로 둠, 또는 한 폴더에 DLL 이 여러 개 | `<DLL 이름>.loh-mod.json` (예: `MyMod.loh-mod.json`) |
| 게임 파일을 고치는 패치 (exe · 스크립트) | 압축 맨 위나 그 바로 아래 폴더, 패치 exe 옆의 `loh-mod.json` |

글자는 UTF-8 로 저장합니다. 배포 압축에 같이 넣으면 모드매니저로 설치할 때 그대로 따라 들어갑니다.

모드의 자체 설치기(bat·스크립트)를 쓰는 경우에도 `loh-mod.json` 이 위 자리에 **설치되게** 해 주세요. 설치기의 참고 자료 목록에만 두면 게임 폴더에 들어가지 않아, 원래 설치기로 깐 사용자는 게시글 링크·업데이트 확인을 못 씁니다(모드매니저로 설치하면 압축 안에 있는 것도 읽습니다).

### 예시

```json
{
  "format": 1,
  "name": "내 모드",
  "version": "1.2.0",
  "page": "https://gall.dcinside.com/mgallery/board/view/?id=san14&no=12345",
  "settings": ["MyMod.ini"],
  "game": "12345678",
  "changes": [
    { "kind": "hook",  "target": "UI_BattleMain.Update", "address": "0x1A2B3C0", "note": "전투 화면 입력" },
    { "kind": "patch", "target": "UI_ShopPanel.Open",    "address": "0x2B3C4D0", "size": 6, "note": "확인 창 건너뜀" }
  ]
}
```

### 칸 설명

| 칸 | 뜻 | 꼭? |
|---|---|---|
| `format` | 양식 버전. 지금은 `1` | 예 |
| `name` | 모드 이름(게시글 제목에서 버전을 찾을 때도 씀) | 권장 |
| `version` | 이 배포판의 버전(`1.2.3`) | 권장 |
| `page` | 게시글 주소(디시 글 등). 첫 버전이라 아직 없으면 빼도 됨 | 선택 |
| `settings` | 사용자가 고치는 설정 파일 이름(모드 폴더 기준). 여러 개면 먼저 열 것을 앞에. 모드매니저로 업데이트할 때 사용자가 고친 파일은 그대로 남깁니다(아래 '자체 설치 압축') | 선택 |
| `game` | 이 모드를 맞춘 게임 빌드 번호(모드매니저 맨 위 '게임 빌드' 의 숫자 = Steam 빌드 ID). 사용자의 게임 빌드와 다르면 모드매니저가 '만든 게임 버전'을 참고로 보여 주고, `changes` 의 주소를 비교할 때도 씀 | 권장 |
| `changes` | 게임 코드에서 고치는 곳 목록(아래) | DLL 모드면 권장 |
| `notes` | 버전마다 바뀐 점(`version` · `date` · `text`). 모드매니저 '패치노트' 창에 그대로 보여 줍니다. 최신을 맨 위에 적어 주세요 | 선택 |
| `github` | GitHub 릴리스로 배포한다면 `작성자/저장소`. 업데이트 확인이 게시글 제목 대신 최신 릴리스를 보고, 새 버전이 있으면 '지금 업데이트' 한 번으로 받습니다. 릴리스 태그는 버전(`v1.2.3`), 릴리스에는 모드매니저에 끌어다 놓으면 설치되는 **`.zip`** 하나를 붙이고(7z·rar 은 받지 못합니다), 릴리스 설명은 패치노트로 보입니다. 미리 공개(prerelease)와 임시 글(draft)은 보지 않습니다 | 선택 |
| `needs` | 이 모드가 돌려면 있어야 하는 다른 파일 목록입니다(파일 이름만 적어도 됩니다). 예: `"needs": ["공통로더.dll"]`. 여러 모드가 함께 쓰는 로더처럼, 이 모드가 직접 넣지 않았거나 다른 모드와 같이 쓰는 파일을 적어 주세요. 모드매니저는 이 파일을 쓰는 모드가 하나라도 켜져 있으면 그 파일을 끄거나 지우지 않습니다 | 선택 |

`changes` 한 줄:

| 칸 | 뜻 |
|---|---|
| `kind` | `hook` = 함수에 끼어들기(원래 함수도 이어서 실행), `patch` = 기계어 바이트를 덮어쓰기 |
| `target` | 고치는 함수. **패치가 와도 안 바뀌는 이름**으로: 난독화 안 된 `클래스.메서드`(예: `UI_GiftPanel.OnOpen`, `Wa_*`, `Ci_*`). 난독화된 곳은 하는 일을 짧게(예: `선물 횟수 검사`) |
| `address` | 지금 게임 버전의 GameAssembly.dll 기준 주소(RVA, 16진수). 게임이 업데이트되면 바뀌므로 `game` 과 함께 |
| `size` | `patch` 일 때 덮어쓴 바이트 수 |
| `note` | 사람이 읽을 짧은 설명 |


## 모드매니저가 DLL 겹침을 알려 주는 방법

- 두 모드의 `target` 이 같으면 겹침입니다.
  - 둘 다 `hook` 이면 **"⚠ 겹침"** — 대부분 함께 동작하지만, 이상하면 하나를 꺼 보라고 안내합니다.
  - 한쪽이라도 `patch` 면 **"⚠ 함께 쓸 수 없음"** — 같은 바이트를 덮어써 둘 중 하나는 깨집니다.
- `address` 는 두 모드의 `game` 이 같을 때만 비교합니다(게임 업데이트로 주소가 바뀌기 때문). 범위가 겹치면 위와 같이 판단합니다. **`game` 을 빼면 주소 비교를 하지 않습니다.**
- 모드매니저는 적힌 내용이 맞는지 확인할 수 없습니다. 빠짐없이, 정확히 적어 주세요.


## 자체 설치 압축 — 끌어다 놓으면 바로 설치되게

압축 안에 `_files\manifest.json`(어떤 파일을 게임 폴더 어디에 둘지 적은 목록)을 넣어 두면, 모드매니저가 모드마다 따로 맞추지 않아도 설치·'지금 업데이트'·'이전 버전으로 되돌리기'·제거를 합니다. 손으로 설치하는 사람을 위한 `설치.cmd` 같은 것은 함께 넣어 두셔도 됩니다(모드매니저는 실행하지 않음).

```
내모드_v1.2.0\
  설치.cmd                 ← 손 설치용(모드매니저는 안 씀)
  _files\
    manifest.json
    LOH_MyMod\LOH_MyMod.dll
    LOH_MyMod\LOH_MyMod.ini
    LOH_MyMod\loh-mod.json
    MODs\내모드\ModInfo.json
```

```json
{
  "product": "LOH_MyMod",
  "version": "1.2.0",
  "files": [
    { "src": "LOH_MyMod\\LOH_MyMod.dll", "dst": "LOH_MyMod\\LOH_MyMod.dll", "sha256": "…" },
    { "src": "LOH_MyMod\\LOH_MyMod.ini", "dst": "LOH_MyMod\\LOH_MyMod.ini", "sha256": "…" },
    { "src": "LOH_MyMod\\loh-mod.json",  "dst": "LOH_MyMod\\loh-mod.json",  "sha256": "…" },
    { "src": "MODs\\내모드\\ModInfo.json", "dst": "MODs\\내모드\\ModInfo.json", "sha256": "…" }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `product` | 모드를 가리키는 이름(영문). 버전이 바뀌어도, 아래 '종류'가 달라도 같게 |
| `version` | 이 압축의 버전(`loh-mod.json` 의 `version` 과 같게) |
| `files` | 넣을 파일 한 줄씩. `src` 는 `_files` 폴더 기준 자리, `dst` 는 **게임 폴더 기준** 자리, `sha256` 은 그 파일의 SHA-256(손 설치 스크립트가 확인할 때 씀) |
| `variant` | 한 압축에 같은 모드를 여러 종류로 넣을 때 이 종류의 이름(예 `밸런스판`) — 아래 |
| `variantNote` | 그 종류의 한 줄 설명(설치 화면에 보임) |

- 모드매니저는 `files` 에 적힌 파일만, `dst` 를 보고 넣습니다: `MODs\<폴더>\…` 는 데이터 모드, `ThreeKingdom_Data\…` 는 게임 파일 교체(원본은 백업했다가 제거할 때 되돌림), DLL 이 든 폴더(`LOH_MyMod\LOH_MyMod.dll`)는 DLL 모드 — 그 폴더의 파일을 모드매니저 폴더(`LOH_ModManager\External\…`)에 두고 모드매니저가 불러옵니다.
- **이 세 곳에 들지 않는 파일은 넣지 않습니다.** 게임 폴더 바로 아래의 DLL·ini 나 DLL 이 없는 폴더의 파일이 그렇습니다. DLL 은 자기 폴더 안에 두세요.
- DLL 은 x64 네이티브여야 합니다. .NET DLL 이나 32비트 DLL 은 설치하지 못합니다.
- `loh-mod.json` 도 `files` 에 넣어 주세요. 안 적으면 설치되지 않아 게시글 링크·업데이트 확인·설정 열기가 안 됩니다.
- 입구 DLL(`entry\…`)·`entries` 칸·설치 스크립트는 모드매니저가 쓰지 않습니다. 손 설치용으로 그대로 두셔도 됩니다.
- 모드매니저는 BepInEx·MelonLoader 같은 로더를 설치하지 않습니다. 이런 로더가 필요한 모드는 사용자가 로더를 따로 설치해야 합니다.

**압축 형식**: 비밀번호가 걸린 zip 은 모드매니저가 비밀번호를 물어서 풉니다. 비밀번호가 걸린 7z·rar 은 풀지 못하므로, 사용자가 직접 푼 폴더를 끌어다 놓아야 합니다.

**종류 여러 개를 한 압축에** (설정 값만 다른 밸런스판·편의판 같은 것): 종류마다 폴더를 따로 두고, 각 폴더의 `manifest.json` 에 같은 `product` 와 서로 다른 `variant` 를 적습니다.

```
내모드_v0.5.3\
  읽어주세요.txt           ← 손 설치: 둘 중 하나의 설치.cmd 실행
  밸런스판\설치.cmd   밸런스판\_files\manifest.json  (… "variant": "밸런스판", "variantNote": "…")
  편의판\설치.cmd     편의판\_files\manifest.json    (… "variant": "편의판",   "variantNote": "…")
```

- 모드매니저 설치 화면에는 종류마다 한 줄이 나오고 하나만 고를 수 있습니다. 처음엔 첫 번째(폴더 이름 순)가 골라져 있습니다.
- '지금 업데이트' 때는 지금 쓰는 종류를 골라 둡니다. **버전이 바뀌어도 종류 이름은 그대로** 써 주세요. 이름이 바뀌면 사용자가 다시 고릅니다.
- 다른 모드를 같은 압축에 함께 넣으면(`product` 가 다름) 모드마다 따로 고르고, 모드매니저에는 모드마다 따로 들어갑니다(켜고 끄기·지우기·업데이트도 모드별). 그래서 합본에 든 모드도 각자 `loh-mod.json`(`github` 등)을 넣어 두면 하나씩 업데이트됩니다.

**업데이트 때 설정 파일**: `loh-mod.json` 의 `settings` 에 적은 파일은, 사용자가 고쳐 썼으면 새 버전에서도 그 내용을 그대로 둡니다('이전 버전으로 되돌리기' 때도 지금 내용이 따라갑니다). 고치지 않은 파일은 새 버전의 기본값이 들어갑니다. 업데이트하면서 다른 종류를 고르면 그 종류의 설정 파일을 씁니다(전에 쓰던 것은 '지운 모드'에 남음). 그러니 새 버전 DLL 은 **옛 버전의 설정 파일도 읽을 수 있게**(새로 생긴 칸이 없으면 기본값) 만들어 주세요.


## 게임 파일을 직접 고치는 패치를 만든다면 (exe · 스크립트)

모드매니저가 따로 맞추지 않아도 받는 형식이 두 가지 있습니다. 설치, 켜고 끄기, 제거, 게임 업데이트 뒤 다시 적용까지 알아서 합니다. 어느 쪽도 아닌 패치는 보통 '지원하지 않는 형식'으로 안내하고, 사용자는 '수동으로 설치'로 넣게 됩니다.

### 방법 1: loh-mod.json 의 `patch` 칸

```json
"patch": {
  "run": "내 패치.exe",
  "items": [
    { "id": "1", "name": "첫째 항목", "note": "짧은 설명" },
    { "id": "2", "name": "둘째 항목" }
  ]
}
```

- `run`: `loh-mod.json` 과 같은 폴더 아래에서 실행할 파일(exe · bat · cmd · ps1). 모드매니저가 보관 폴더에서 실행하고, 게임 폴더는 `--game "<게임 폴더>"` 로 알려 줍니다.
- 적용: `--game "<게임 폴더>" --items 1,2` — 고른 항목만 넣습니다. `items` 가 없으면 `--items` 없이 전부 넣습니다. 이미 들어간 항목은 그대로 둡니다.
- 되돌리기: `--game "<게임 폴더>" --restore` — 이 패치가 바꾼 것을 모두 되돌립니다.
- 성공하면 종료 코드 0, 실패하면 0이 아닌 값을 돌려주세요.
- 실행 조건: 창을 띄우지 않고 입력을 닫은 채 돌립니다(묻는 화면이 있으면 안 됩니다). 15분 안에 끝나야 합니다. 출력은 UTF-8 로 읽고, **실패하면 마지막 줄을 사용자에게 그대로 보여 주므로** 이유를 마지막 줄에 적어 주세요.
- 새 패치는 목록 맨 아래(지금 파일 위)에 먼저 넣어 봅니다. 여기서 실패하면 그 이유를 보여 주고, 게임 파일을 실행 전 상태로 되돌립니다.
- 모드매니저는 실행 전후로 바뀐 파일을 기록해 두고, 다른 패치와 함께 쓸 때는 원본에서 순서대로 다시 적용합니다. 그래서 다른 패치가 먼저 들어간 파일에서도 동작해야 합니다(아래 참고).

### 방법 2: 가이드 방식 (`loh-mod.json` 없이도 됨)

커뮤니티 '모드패치 궁극 가이드' 20장의 모양입니다. 파일을 따로 고치지 않아도 이 모양이면 받습니다.

- 설치 bat 에 이런 줄이 있습니다: `powershell … -File "%~dp0내패치.ps1" 1 2 %*` (`1 2` 는 그 bat 이 넣을 번호)
- ps1 이 `[string]$GameDir` 과 `[switch]$Yes` 를 받습니다.
- 한 폴더의 bat 들이 가리키는 ps1 은 하나여야 합니다. 압축 맨 위나 그 바로 아래 폴더에 두고, bat 줄에 자체 변수나 `-GameDir`·`-Yes` 를 직접 쓰지 않습니다.
- 모드매니저는 `<번호> -GameDir "<게임 폴더>" -Yes` 로 실행합니다. 종료 코드 0 = 됨, 그 밖 = 못 넣음(마지막 줄을 그대로 보여 줌).
- 이름에 `원래대로`·`복구`·`되돌리`·`제거`·`삭제`·`restore`·`uninstall`·`remove` 가 든 bat 의 번호는 되돌리기로 씁니다. 설치 bat 이 여럿이면 사용자가 고릅니다.
- `ModInfo.json` 이 든 압축은 데이터 모드로 봅니다.
- 맨 아래에서 거절하면 모드매니저가 사용자에게 묻고 '패치 자리 찾기'로 다른 패치 위 자리를 차례로 시험합니다. 이 기능은 가이드 방식에서만 됩니다.
- 없어도 받지만 있으면 좋은 것: 받은 `-GameDir` 이 게임 폴더가 아니면 멈추기, `-Yes` 면 'Enter 를 누르면…'에서 기다리지 않기, 되돌리기 bat 짝 두기.

### 다른 패치와 같이 쓰이려면

모드매니저가 없어도 마찬가지입니다.

- 원본인지는 파일 크기나 날짜가 아니라 **고칠 자리의 원래 바이트**로 확인해 주세요. 크기로 막으면 다른 패치가 이미 들어간 파일에서는 통째로 거부됩니다.
- 새 코드를 넣을 구역을 덧붙인다면, 원본 파일 끝의 고정 주소가 아니라 **이미 있는 마지막 구역 뒤**에 붙이고 건너뛰는 주소도 그 위치로 계산해 주세요. 고정 주소를 쓰면 먼저 들어간 패치와 부딪힙니다.
- 구역을 붙일 때는 구역 표 뒤 빈칸(한 칸 40바이트)이 필요하고, 이 빈칸은 여러 패치가 나눠 씁니다. 모드매니저는 2칸 이하로 남으면 사용자에게 알립니다. 구역은 꼭 필요한 만큼만 만들어 주세요.
- 되돌리기는 **자기가 바꾼 자리만** 원래 바이트로 돌려 주세요. 보관해 둔 원본 파일로 통째로 덮어쓰면 그 위에 들어간 다른 패치까지 지워집니다.
- 다시 실행해도 두 번 들어가지 않게, 이미 적용됐는지 확인해 주세요.
- 번호를 고르는 화면이 있다면 명령으로도 고를 수 있게 해 주시면 좋습니다 (예: `--items 1,2`, `--restore`). 성공하면 종료 코드 0.

게임이 업데이트되면 스팀이 게임 파일을 새 원본으로 바꿔 패치가 풀립니다. 모드매니저가 이를 알려 주고 다시 적용하지만, 패치가 새 게임 버전을 받아 줘야 들어갑니다.

`loh-mod.json` 의 `changes` 에는 덧붙인 구역도 한 줄로 적어 주세요 (`target` 에 구역 이름과 하는 일, 예: `.mymod 구역 · 보조 코드`).


## 업데이트 확인 — 게시글 제목 규칙

- 글 하나에 모드 하나: 제목에 버전 하나 (`v1.2.3`, `(1.2.3)`).
- **버전은 점이 있는 숫자만 읽습니다.** `v2`, `3차` 는 버전으로 읽지 못합니다.
- 제목에 게임 버전 같은 다른 숫자도 쓴다면 모드 이름 바로 뒤에 버전을 적어 주세요(`내 모드 1.2.3 (게임 v1.0.13)`). 이름 뒤에 없는데 숫자가 둘이면 버전을 읽지 못합니다. 이름의 띄어쓰기는 달라도 됩니다.
- 버전 없이 날짜만 있으면(`12/24 업뎃`, `10월 22일`, `(261017)`) 그 날짜가 사용자가 모드를 넣은 날보다 뒤일 때 "새 소식(새 버전일 수 있음)"으로 알립니다. 연도 없는 날짜는 올해(아직 안 온 날이면 작년)로 봅니다. 버전이 있으면 버전이 먼저입니다.
- 업데이트 확인은 게시글 조회수에 영향을 주지 않습니다.
- 한 글에 모드 여러 개: `모드이름 1.2.3` 을 나란히 (`(모드A 0.5.2 · 모드B 1.1.0)`). 이때는 이름 없는 숫자 하나로 추측하지 않습니다.
- 디시 제목은 40자까지입니다.
- 새 버전을 올릴 때 **같은 글을 고쳐 쓰면** 게시글 주소가 그대로라, 두 번째 버전부터는 `page` 를 처음부터 넣어 배포할 수 있습니다. 첫 버전은 `page` 를 비워도 됩니다.
- 모드매니저는 사용자가 '업데이트 확인'을 누를 때와, 사용자가 켜 둔 경우 하루 한 번 자동 확인 때만 게시글 제목을 읽습니다(자동 확인은 처음엔 꺼져 있습니다). 받기·설치는 사용자가 '지금 업데이트'를 누를 때만 합니다.


## 링크만 넣고 싶을 때

브라우저 주소창의 자물쇠 아이콘을 모드 폴더로 드래그하면 `글제목.url` 바로가기가 생깁니다. 이 파일만 있어도 모드매니저가 게시글 링크로 씁니다(`loh-mod.json` 의 `page` 가 먼저).

링크를 고르는 순서: 사용자가 모드매니저에서 직접 넣은 링크 → `loh-mod.json` 의 `page` → 모드 폴더의 `.url` → 모드매니저가 원래 알고 있는 링크.


## AI 로 모드를 만든다면 — 그대로 붙여 넣을 지시문

**모든 모드**

> 이 모드 배포판에 `loh-mod.json`(영웅입지전 모드 정보 양식 버전 1)을 넣어 줘. 모드 DLL 과 같은 폴더(데이터 모드면 MODs 아래 모드 폴더)에 두고, `format` 은 1, `name`·`version` 은 이 모드 것, `page` 는 게시글 주소가 있으면 넣고 없으면 빼. 사용자가 고치는 ini 가 있으면 `settings` 에 파일 이름을 적어. `notes` 에 버전마다 바뀐 점(`version`·`date`·`text`)을 최신이 맨 위로 오게 적어. GitHub 릴리스로 배포하면 `github` 에 `작성자/저장소` 를 적고, 다른 모드와 같이 쓰는 로더 같은 파일이 있으면 `needs` 에 적어. 모르는 칸은 빼고, 추측해서 채우지 마.

**DLL 모드라면 덧붙이기**

> `game` 에는 맞춘 게임 빌드 번호(Steam 빌드 ID, 모드매니저 맨 위에 나오는 숫자)를 적고, `changes` 에는 이 모드가 GameAssembly 의 코드에 끼어드는(hook) 곳과 기계어를 덮어쓰는(patch) 곳을 **빠짐없이** 한 줄씩 적어 줘. `target` 은 게임 패치로 안 바뀌는 이름(난독화 안 된 `클래스.메서드`)으로, 난독화된 곳은 하는 일을 짧게 적고, `address` 는 지금 게임 버전 GameAssembly.dll 기준 RVA 16진수, patch 면 `size` 에 바꾼 바이트 수를 적어.

**데이터 모드라면 덧붙이기**

> 다른 모드와 함께 쓰기 좋게 만들어 줘. `ModInfo.json` 은 `[ { … } ]` 목록으로 쓰고, `strIDEnd` 는 남과 겹치지 않는 값으로 정해 버전이 바뀌어도 그대로 둬. 표에는 실제로 바꾼 줄만 넣고, 고치지 않은 원작 줄은 복사하지 마. 새 항목과 새 카드는 번호 끝에 `strIDEnd` 를 붙인 새 번호로 만들고, 카드 연출은 원작 번호 파일을 덮지 말고 새 카드로 넣어. `InteractOption.json` 이 있으면 빈 `[]` 라도 `ConversationCondition.json` 을 넣어. 원작 카드 번호의 연출을 꼭 바꿔야 하면 모드 설명에 '켜진 데이터 모드 중 목록 맨 아래에 두어야 함'이라고 적어.

**게임 파일을 직접 고치는 패치라면 덧붙이기**

> 이 패치가 다른 패치가 먼저 들어간 GameAssembly.dll 에서도 동작하게 해 줘. 원본인지는 파일 크기 대신 고칠 자리의 원래 바이트로 확인하고, 새 구역은 이미 있는 마지막 구역 뒤에 붙이고(가상 주소 · 파일 위치 정렬, 구역 표 다음 칸, SizeOfImage 갱신) 건너뛰는 주소도 그 위치로 계산해. 되돌리기는 바꾼 자리만 원래 바이트로 돌리고, 다시 실행해도 두 번 안 들어가게 해. loh-mod.json 에 patch 칸(run, items)을 넣고, `--game <폴더> --items 1,2` 와 `--game <폴더> --restore` 를 창이나 입력 없이 처리해. 출력은 UTF-8 로, 실패 이유는 마지막 줄에 쓰고, 성공하면 종료 코드 0. changes 에 덧붙인 구역도 적어.

**배포 압축을 모드매니저가 바로 설치하게 하려면 덧붙이기**

> 배포 압축을 자체 설치 형식의 .zip 으로 만들어 줘: `<모드>_v<버전>\_files\manifest.json` 에 `product`(영문 모드 이름, 버전이 바뀌어도 같게)·`version`·`files`(`src` 는 `_files` 기준, `dst` 는 게임 폴더 기준, `sha256`)를 적고, `loh-mod.json` 도 `files` 에 넣어. DLL 은 게임 폴더 바로 아래가 아니라 자기 폴더 안에 둬. 설정 값만 다른 종류가 있으면 종류마다 폴더를 따로 두고 각 manifest 에 같은 `product` 와 `variant`(종류 이름, 버전이 바뀌어도 같게)·`variantNote`(한 줄 설명)를 적어. 새 버전 DLL 은 옛 버전의 설정 파일도 읽게(없는 칸은 기본값) 해 줘.
